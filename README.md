# EDGE Challenge — Ambulance Network Handover Prototype (ATP2026)

This project simulates an ambulance streaming live patient data to a
hospital while switching networks mid-trip, and compares how **TCP**
and **QUIC** each handle that switch.

See [`REQUIREMENTS.md`](./REQUIREMENTS.md) for what the system does,
what's implemented, and what's still missing.

## Folder structure

```
edge-ambulance-quic/
├── README.md
├── REQUIREMENTS.md
└── src/
    ├── 01_baseline_socket/            # simplest TCP client/server, proves basic communication
    ├── 02_baseline_with_measurement/  # adds automatic disruption-time measurement
    ├── 03_tcp_handover_demo/          # TCP handover experiment (control group)
    ├── 04_quic_handover_demo/         # QUIC handover experiment (the actual solution)
    └── 05_visualization/              # comparison charts (matplotlib)
```

Each numbered folder is a self-contained step. They are numbered in the
order they should be run/understood, matching the order they were built
in during development.

## Requirements

- Python 3.10 or newer (tested with 3.14)
- Packages: `aioquic`, `matplotlib`, `cryptography` (installed
  automatically as a dependency of `aioquic`)

Install everything with:

```
py -m pip install aioquic matplotlib
```

## How to run each part

### 1. Baseline TCP communication (`src/01_baseline_socket/`)

Proves the ambulance (client) and hospital (server) can talk to each
other at all.

```
cd src/01_baseline_socket
py hospital_server.py
```

In a **second terminal**, in the same folder:

```
py ambulance_client.py
```

You should see the client sending a message every second, and the
server printing each one as it arrives. Stop the client with `Ctrl+C`.

### 2. Baseline with disruption measurement (`src/02_baseline_with_measurement/`)

Same as step 1, but the ambulance pauses for 5 seconds after message
#10 (simulating a dead zone), and the hospital server automatically
measures and prints how long the gap lasted.

```
cd src/02_baseline_with_measurement
py hospital_server_v2.py
```

Second terminal, same folder:

```
py ambulance_client_v2.py
```

### 3. TCP handover demo (`src/03_tcp_handover_demo/`)

Simulates a real handover: the ambulance closes its connection and
reconnects from a different local port (Wi-Fi → cellular), and we
observe that the hospital sees this as **two separate sessions**.

```
cd src/03_tcp_handover_demo
py hospital_server_tcp_migration.py
```

Second terminal, same folder:

```
py ambulance_client_tcp_migration.py
```

**Expected output (server):** two separate `NEW SESSION #...` messages.

### 4. QUIC handover demo (`src/04_quic_handover_demo/`)

The core experiment. Same handover scenario as step 3, but using QUIC —
the hospital should see **one continuous session**, with no reconnect.

**First time only** — generate a TLS certificate (creates `cert.pem`
and `key.pem` in this folder):

```
cd src/04_quic_handover_demo
py generate_certificate.py
```

Then run the server:

```
py hospital_server_quic.py
```

Second terminal, same folder:

```
py ambulance_client_migration.py
```

**Expected output (client):** a line like
`Migration completed in 1.5xxs (SAME session, no reconnect needed)`,
and the server keeps receiving all 10 messages without any
"new session" message in between.

### 5. Generate comparison charts (`src/05_visualization/`)

After running steps 3 and 4 and noting down the results (see
"Recording results" below), generate the comparison charts:

```
cd src/05_visualization
py plot_results.py
py plot_timeline.py
```

This produces `comparison_result.png` and `timeline_result.png` in the
same folder.

## Recording results

The numbers used in the charts (`sessions_created`, `times` inside
`plot_results.py`) are currently **entered by hand**, based on what is
printed in the terminal when running steps 3 and 4. There is no
automatic logging yet (see `REQUIREMENTS.md` for this as a planned
improvement). If you re-run the experiments and get different numbers,
update the values at the top of `plot_results.py` and `plot_timeline.py`
accordingly before re-running them.

## Notes

- All experiments currently run on a single machine using `127.0.0.1`
  (loopback) with different **local ports** to simulate different
  networks. This is explained and justified in the project report.
- The self-signed certificate generated by `generate_certificate.py` is
  for local testing only and should not be reused for any real
  deployment.
